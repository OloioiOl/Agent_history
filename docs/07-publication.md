# GitHub 공개와 개인 운영 기록

## 공개본에 담은 것

구조, 실패 원인, 제한, 검증 범위, 축약 증거, 브리지 소스, fake 및 로컬 테스트. 운영 서버 주소, Discord 사용자·채널 식별자, 토큰, 인증 디렉터리 내용, 사적 원문 문서, raw 모델 출력은 포함하지 않는다. 이번 시험에 사용한 프로젝트 자체 문서의 고정본은 근거로 포함한다.

기존 서버용 설치·복구·활성화 스크립트는 특정 경로·UID·코드 해시에 의존하므로 공개 패키지에 복사하지 않았다. `bridge/`는 검토·테스트용 소스이며 즉시 설치 가능한 배포판이 아니다. `examples/`에는 가상 경로·계정의 systemd 유닛과 설정 키 예시를 제공하며, 실제 운영 설정으로 오해하지 않도록 전제와 미검증 범위를 적었다.

## 로컬 보존 원칙

원본 운영 로그와 사적 문서는 비공개 위치에 둔다. 이번에 입력으로 사용한 프로젝트 자체 문서의 고정본은 `evidence/normal-document-source-20261011.txt`에 포함한다. 현 세션의 진단·배포 자료는 Git에서 제외된 `private/`에 보관하며 별도 비공개 백업이 필요하다. `.gitignore`는 실수 방지 장치일 뿐 이미 추적한 비밀을 제거해 주지 않는다. 추적 파일에는 인증 토큰과 비공개 서버 접속 정보를 기록하지 않는다. Git 원격 연결 설정은 별도로 존재한다.

## 게시 상태

2026-10-13 공개 준비 시 GitHub API로 **PRIVATE**, 기본 브랜치 `main`, 브랜치 1개와 태그·이슈·PR·릴리스·Actions 실행 기록 없음을 확인했다. 사용자가 이메일 처리, 최신 변경 커밋·push, 공개 전환을 승인했다.

첫 커밋의 작성자·커미터 이메일을 GitHub `noreply` 주소로 변경하고 이 저장소의 향후 커밋에도 적용했다. 이력 재작성으로 커밋 ID가 바뀌었으며 최초 파일 내용과 원래 작성 시각은 보존했다. 최신 변경을 커밋·push했고 원격 `main` 이력의 이메일도 확인했다.

공개 직전 검사에서 브랜치 이력에서 제거한 옛 커밋이 GitHub에서 해시로 여전히 조회되는 것을 확인했다. 사용자가 옛 커밋의 이메일 노출 가능성을 수락하고 공개를 재승인하여, 2026-10-13 공개로 전환한 뒤 GitHub API에서 **PUBLIC** 상태를 확인했다. 현재 브랜치의 이메일 변경과 GitHub에 남은 옛 객체 제거는 구분한다. 공개 라이선스는 미지정이다. 커밋 날짜를 과거 작업 시점처럼 소급하지 않는다.

## 나중에 추가할 자료

- 회고로 확보한 초기 중계 사례를 뒷받침하는 원문 전후 로그: 입력, 요청, 변형 결과. 로그가 없으면 관찰 회고로 유지.
- [확보된 정상 파일 운영 시험](11-validation-20261011.md)을 바탕으로 한 짧은 데모 및 대표 강의 문서의 추가 평가.
- 필요할 경우 독립 봇·opencode·보안 실습 환경의 별도 소스 및 근거.

서버 상태나 서비스 시작 시각은 지속적으로 변한다. 운영 기록은 2026-10-08 및 2026-10-11에 받은 출력 기준이며, 현재 상태 조회 도구를 대신하지 않는다.
