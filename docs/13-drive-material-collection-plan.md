# Google Drive 수업 교재 수집과 의미 평가 계획

작성일: 2026-10-11. 사용자와의 대화에서 확인한 제공 방식과 후속 계획을 기록한다. **설계 단계이며 Drive 접속·수집기 구현·예약 실행·추가 모델 호출은 아직 수행하지 않았다.**

## 확인한 요구와 미확인 사항

사용자 설명에 따르면 교재는 일부 계정만 접근 가능한 하나의 공유 폴더에 모여 있다. 사용자는 열람·다운로드가 가능하지만 수정 권한은 없다. 강사가 매 수업 Google 문서에 직접 작성하며, 완성형 교재가 배포되는 방식이 아니다. 이 조건은 사용자 확인 사항이며 실제 계정·파일 권한을 API로 검증한 결과는 아니다.

다음 사항은 시작 전에 확인한다.

- 공유 폴더 링크와 인증에 사용할 접근 권한 보유 계정.
- 한 문서에 여러 날 내용을 누적하는지, 수업·주제별로 새 문서를 만드는지.
- 하위 폴더·바로가기·문서 탭·표·이미지 등 실제 자료 구성과 수집 대상 범위.
- 로컬 저장 위치, 반복 수집을 실행할 PC 또는 서버, 수업 일정.

## 수집 방식

**Python + Google Drive API로 변경을 확인하고, 수집 시점별 사본을 보존하는 방식**을 우선 설계한다. rclone은 일괄 복사 대안이지만, 이 작업에서는 수업별 연결·사본 이력·분석 입력의 출처를 함께 관리하는 것이 중요하다.

원격 자료를 읽어 로컬에 저장하며 강사의 문서를 수정하지 않는다. 사용자 인증은 본인 브라우저에서 진행하고 비밀번호·토큰을 채팅이나 Git에 넣지 않는다. 읽기 전용 권한을 우선 검토하되, 실제 OAuth 범위와 조직의 앱 허용 여부는 연결 단계에서 확인한다. 프로그램의 수집 대상을 지정 폴더로 제한하는 것과 OAuth 권한 자체가 그 폴더로 제한되는 것은 구분한다.

수집과 모델 분석은 별도 단계로 둔다. 교재에 변경이 생겼다는 이유만으로 유료 분석을 시작하지 않는다.

## 진행 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1. 목록 확인 | 폴더 구조, 파일 ID·형식·수정 정보·다운로드 가능 여부 조회 | 대상 목록과 제외 범위를 검토할 수 있음 |
| 2. 문서 1개 수집 | 분석용 텍스트 및 표·이미지 확인용 보존 형식으로 내보내기 | 실제 문서와 대조해 본문·탭·표·이미지의 보존 및 누락 범위를 기록함 |
| 3. 변경과 사본 관리 | 신규·변경 문서 감지, 수집 시각별 저장, 해시·이력 기록 | 이전 사본을 덮어쓰지 않고 변경·실패 상태를 구분함 |
| 4. 자막 연결 | 수업 날짜와 교재 사본·구간 연결 | 날짜 판단 근거와 불확실성이 기록됨 |
| 5. 반복 수집 | 수동 검증 후 실행 장소·시간을 확정해 예약 | 신규·수정·이름 변경·접근 실패 처리 확인 후 예약 상태를 검증함 |
| 6. 의미 평가 | 대표 자료·질문·기준 재확정 후 승인된 실행 | 위치 일치·의미 지지·최종 답변 보존을 분리해 보고함 |

### 변경 감지와 저장 원칙

파일 이름 대신 파일 ID로 문서를 식별하고 원격 수정 정보로 수집 필요 여부를 판단한다. 내보낸 내용의 해시도 기록한다. 원격 수정 정보 변화와 본문 내용 변화는 같은 의미로 취급하지 않는다.

내보내기 전후 수정 정보를 비교해 수집 중 변경 여부를 확인한다. 변경이 관측되면 불안정한 수집본으로 표시하고 분석 입력 확정을 보류한다. 이 비교만으로 여러 형식의 내보내기가 원자적으로 같은 순간의 문서임을 보장한다고 주장하지 않는다.

실패한 다운로드는 완료된 사본으로 등록하지 않는다. 기존 사본은 유지하며 접근 권한 상실·원격 삭제를 이유로 과거 로컬 사본을 자동 삭제하지 않는다. 주기 사이의 모든 편집 과정을 복원하는 시스템이 아니라 **관측한 시점의 사본을 보존하는 시스템**이다.

권장 기록 항목은 다음과 같다. 실제 스키마는 구현 시 확정한다.

| 구분 | 기록 항목 |
|---|---|
| 출처 | 파일 ID, 제목, 원문 링크, 대상 폴더 ID |
| 원격 상태 | 문서 형식, 수집 전후 수정 시각·버전 정보(확보 가능한 범위) |
| 수집본 | 수집 시각과 시간대, 내보내기 형식, 저장 경로, 바이트 수, SHA-256 |
| 처리 결과 | 성공·실패·수집 중 변경, 오류 사유, 형식별 보존 한계 |
| 수업 연결 | 수업 날짜, 자막 식별자, 교재 구간, 연결 근거와 검토 상태 |

원문 링크와 교재 내용, 인증 정보 및 상세 수집 이력은 비공개 저장 영역에 둔다. 공개용 기록에는 필요한 최소한의 상태만 남긴다.

### 수업별 연결과 반복 실행

수업 종료 후 한 번 수집하고 다음 수업 전에 변경 여부를 확인하는 방식을 초기 제안으로 둔다. 정확한 시간과 실행 환경은 아직 정하지 않았으며 예약 작업도 만들지 않았다. 수업 중 자료가 필요한 경우 주기적 수집을 별도로 검토한다.

한 문서가 여러 날 누적되는 경우 제목·본문의 날짜·수업 구간을 확인한다. 원격 수정일만으로 수업 날짜를 정하지 않는다. 수집 시각 역시 강사의 작성 완료 선언이 아니다. 예를 들어 ‘10/11 수업 종료 후 수집본’과 ‘10/12 수정 후 수집본’을 구분해 보존한다.

분석에는 사본 하나와 해시를 고정한다. 이후 교재가 바뀌면 새 입력 버전으로 다루며, 기존 평가에 사용한 근거를 덮어쓰지 않는다.

## 기존 의미 평가와 연결

[10/8 자막 평가 준비](12-lecture-semantic-review-20261011.md)의 7,147바이트·145줄 입력, 질문 5개와 평가자용 기준은 그대로 보존한다. 교재 수집 방식을 먼저 확인한 뒤 해당 구간에 대응하는 교재가 있는지 조사한다.

교재를 추가할 경우 원문·발췌·크기·질문·해시를 다시 고정하고 **자막 단독 시험과 다른 입력 버전**으로 기록한다. 기존 자막의 크기를 교재 포함 입력의 크기로 표시하지 않는다. 교재가 없거나 연결이 불명확하면 그 상태를 명시하고 평가 범위를 정한다.

후속 실행 제안은 `flash`, agy CLI 최대 1회, 자동 재시도 없음이다. 교재 포함 입력이 정해진 뒤 외부 전송 및 호출 범위를 승인받는다. Hermes 응답 생성과 agy 내부 모델 단계는 CLI 1회와 별도 기록한다. 평가자용 정답·검토 메모는 모델 입력에 넣지 않는다.

실제 결과에서는 인용의 파일·줄·문자열 일치, 주장 전체에 대한 선택 인용의 의미적 지지, Hermes 최종 답변의 누락·추가·변형을 별도로 평가한다. AI 보조 검토와 사람의 품질 승인을 구분한다.
