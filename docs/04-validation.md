## 2026-10-11 후속 검증

- 5,807바이트 프로젝트 문서의 첫 시도는 `finish` 근거 개수 5개가 상한 3개를 넘어 실패했다. 개별 인용 13개는 일치했어도 제출 전체는 실패다.
- 프롬프트에 기존 한도를 명시한 뒤 같은 입력·질문·모델 별칭으로 두 번째 시도를 수행했다. 6개 finding, 근거 수 `3·3·3·1·2·2`, 정확한 인용 14개로 성공했다.
- 저장된 응답과 Hermes의 실제 도구 반환 JSON이 일치했다. 최종 저장 답변도 Markdown 표시용 들여쓰기를 제외하면 인용 파일·줄 범위·문자열 14개를 그대로 보존했다. Discord 실제 전달은 사용자 제공 3개 분할 메시지로 확인했다.
- Linux Python 3.12.3에서 동일 프롬프트 수정본의 임시 복사본으로 fake 시험 31개 통과, 실패·오류·skip 0개를 확인했다. 모델 호출과 운영 파일 변경은 없었다.

## 외부 검증자가 전한 Linux Python 3.10 시험

2026-10-08 사용자가 전달한 검토문에는 Linux VM의 임시 복사본에서 31개 중 30개 통과, `test_async_client_cancellation` 1개 실패가 보고됐다. 검증자는 Python 3.10에 `asyncio.timeout`이 없는 점을 원인으로 설명했다. 소스가 이 API를 사용하며 저장소 요구 버전은 3.11 이상이다.

이는 **검증자 제공 요약**이다. 이후 검증자가 명령(`PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest -v test_bridge test_result_contract`, 저장소 밖 임시 복사본), Python 3.10.12, 실행 소스가 [당시 manifest](../evidence/manifest-20261008.json) 해시와 일치함을 추가로 알려 왔다. 전체 로그는 받지 않았고 이 환경에서 재실행하지 않았다. 지원 버전의 전체 Linux 통과나 기존 12개 skip의 검증 완료로 합산하지 않는다. [구조화된 참고 기록](../evidence/external-review.json)에도 이 구분을 유지한다.

2026-10-08 문서 보강 작업에서는 런타임 코드를 변경하지 않았다. [보강 검사 기록](../evidence/review-checks.json)은 링크·예시·소스 불변성 확인이며 새 Linux/모델 실행 결과가 아니다.
